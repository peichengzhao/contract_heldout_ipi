# AgentDojo 协商共进化实验总结（2026-09-09）

## 1. 实验目的

在 AgentDojo（workspace 套件）上跑小规模攻防共进化，验证两件事：

1. **规则协商不能再放开结构化注入格式**（自然语言限定被宪法钉死）。
2. **攻击侧反馈回路能真正跑起来**：资格失败、或录取后被当前防御挡住时，优先改写具体注入文本，而不是只改攻击生成器系统提示。

本轮是在上一轮「协商共进化能跑通，但攻击反馈几乎没触发」之后的修正复跑。

## 2. 实验设置

| 项目 | 内容 |
|------|------|
| 规模 | 3 个任务对 × 3 轮训练（先小后大） |
| 协议 | 军备竞赛式共进化；每轮先协商再开打 |
| 防御初始形态 | 无额外防御配置，只演化任务智能体系统提示 |
| 攻击模型 / 防御模型 / 任务智能体 | deepseek-v4-flash |
| 规则裁判 | gpt-5.6-sol（仅裁决规则，不承担攻击角色） |
| 配置文件 | `model_api_ablation.py` |
| 结果文件 | `results/dojo_negotiated_payload_iter_3x3_p1p2.json` |
| 日志 | `results/dojo_negotiated_payload_iter_3x3_p1p2.log` |
| 完成时间 | 2026-09-09 约 15:43（北京时间） |

本轮相对上一轮的代码改动：

- **自然语言硬锁**：协商结果即使提议 YAML/JSON，也会被钳回「只允许自然语言」。
- **资格失败也反馈**：未录取但对上有可诊断轨迹时，先改写注入文本并放入下一轮优先种子队列。

## 3. 指标怎么读（不用英文简称）

| 中文名称 | 含义 |
|----------|------|
| 资格录取 | 在资格管道上打成功并过线，才有资格去打「当前防御」 |
| 新录取攻击成功率 | 本轮已录取攻击，打当前防御提示词时成功的比例 |
| 历史攻击回放成功率 | 档案里旧攻击，重放到当前防御上仍成功的比例 |
| 防御提示词版本 | 任务智能体系统提示被改了几版 |
| 攻击生成器版本 | 攻击侧系统提示被改了几版 |
| 注入文本改写次数 | 失败后对具体 payload 做诊断改写的次数 |
| 无注入任务完成率 | 没有攻击时，智能体能否正常完成用户任务（应接近满分） |

## 4. 主要结果

### 4.1 分轮表现

| 训练轮 | 资格录取 | 新录取攻击成功率 | 历史攻击回放成功率 | 防御提示词版本 | 攻击生成器版本 | 档案条数 |
|--------|----------|------------------|--------------------|----------------|----------------|----------|
| 第 0 轮 | 3/3 | 约 86.7% | 约 53.3% | 1 | 0 | 3 |
| 第 1 轮 | 1/3 | 0% | 40% | 1 | 0 | 4 |
| 第 2 轮 | 1/3 | 0% | 36% | 1 | 0 | 5 |

### 4.2 终局与过程事件

- **无注入任务完成率**：100%（正常办事能力保住了）。
- **终局历史回放**：攻击成功率约 44%，任务完成率 100%，安全率约 56%。
- **防御提示词**：0 → 1（第 0 轮，因攻击成功打了一次增量补丁）。
- **攻击生成器提示词**：始终为 0（本轮优先产出了注入文本种子，按设计跳过了改攻击系统提示）。
- **注入文本改写**：共 **6 次**，且 6 次都产出了可复用种子。
  - 2 次触发原因：录取后被当前防御挡住
  - 4 次触发原因：资格赛未录取（近成功/部分成功）
- **三轮协商**：均锁定为「只允许自然语言」；结构化格式未被重新打开。

### 4.3 防御补丁内容（最终任务智能体提示，摘要）

## 5. 和上一轮（修正前）比，说明了什么

| 维度 | 修正前那次 | 本轮（P1+P2） |
|------|------------|----------------|
| 协商格式 | 裁判曾锁出 YAML/JSON 等结构化格式 | 三轮都钉死自然语言 |
| 第 0 轮资格 | 往往只有 1/3 能录取 | **3/3 全录取** |
| 新录取攻击 | 每轮仍接近全成功，攻击反馈很少触发 | 第 0 轮很强，第 1–2 轮新录取攻击成功率掉到 **0** |
| 注入文本改写 | 0 次 | **6 次**，回路已通 |
| 防御提示词 | 0→2，主要封旧样本 | 0→1；对「新录取攻击」压制更明显 |
| 历史回放 | 可掉到 0，但攻击侧几乎不学习 | 仍约 36%–44%，旧攻击未完全死光 |

直觉结论：

1. **自然语言硬锁有效**：协商不再把攻击面冲回结构化垃圾格式。
2. **攻击反馈回路有效**：挡住或资格失败后，确实在改写注入文本。
3. **防御暂时占上风（对新攻击）**：第 1–2 轮新录取攻击打当前防御全失败。
4. **攻击侧还没靠改写重新打穿**：有种子、有改写，但后续轮次新录取攻击成功率仍为 0；说明「有反馈」不等于「已经反击成功」。
5. **任务可用性保住**：无注入完成率始终满分，防御补丁没有变成全面拒答。

## 6. 过程故事（按时间线）

1. **第 0 轮**：三个注入目标全部资格过线，多数打穿当时防御；防御据此把提示词升到第 1 版。
2. **第 1–2 轮**：新录取攻击打第 1 版防御失败（被识别/挡住）；未录取的对上也触发注入文本改写。
3. 改写后的种子进入后续候选队列，但在本 3×3 窗口内**尚未观察到新录取攻击重新打穿**。
4. 历史档案回放成功率缓慢下降，说明旧攻击也被部分削弱，但终局仍约四成成功。

## 7. 局限

- 规模仍是 **3×3 冒烟**，不能外推到完整 9×8。
- 单次运行、耗时约数小时，方差可能不小。
- 攻击生成器系统提示未升级；本轮进化几乎全靠「注入文本改写 + 模板/档案变异」。
- 尚未做 heldout / 冻结防御后的独立评测。

## 8. 建议的下一步

1. **P0（仍待做）**：防御刚升级后，立刻用「刚成功的那条攻击」对新提示词再打一枪；若被挡，当场改写并入种子——缩短「挡到学」的延迟。
2. 在同样 3×3 上再跑一轮，专门看：注入文本改写之后，**新录取攻击成功率是否回升**（是否出现挡→改→再穿的锯齿）。
3. 指标稳定后再放大规模，并做冻结防御后的 heldout 评测。

## 9. 一句话结论

本轮实验**成功验证了规则硬锁与攻击侧注入文本反馈**；防御在第 0 轮补丁后明显压住了新录取攻击，任务能力未受损，但攻击改写尚未在本窗口内重新打穿当前防御，共进化仍需继续加强「防住之后立刻反击」的闭环。
